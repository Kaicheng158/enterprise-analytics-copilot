# Phase 5.7b protected local Agent HTTP integration

## Scope

Phase 5.7b supplies a localhost-only integration profile for the Phase 5.7a API. It proves that an HTTP request can submit the existing quarterly-sales task, run the already implemented durable Agent stack, persist Checkpoints and Receipts in PostgreSQL, and read the final result through the task-status route.

The profile does not add another Planner, Executor, state machine or database schema. It composes the existing deterministic demo Plan provider, `DurableControlledPlanner`, `DurableWorkerRuntime`, authorized PostgreSQL Tool Registry/Executor, `PostgresCheckpointStore` and `DurableAgentTaskController`.

## Guards and isolation

Three controls must all hold:

- `INTERNAL_AGENT_LOCAL_SERVICE_ENABLED=true` is explicitly set; its default is false;
- `INTERNAL_AGENT_API_ENABLED=true` and a server-held key of at least 32 characters are configured;
- the ASGI peer address is an actual loopback address. Forwarded headers are ignored.

The local service creates a uniquely named `eac_local_agent_*` PostgreSQL database at startup, applies the existing migrations and synthetic sales seed only there, and drops it on graceful shutdown. The database name is generated by the server and cannot be supplied by the client. The service is absent from the normal FastAPI and RAG applications and from Docker Compose.

The local controller serializes submissions. Concurrent copies of one scoped idempotent request therefore generate one Plan, execute one durable workflow and share one result. A repeated key with a different request returns a conflict. Tool authorization, Receipt deduplication, Lease renewal and CAS fencing remain inside the existing runtime and store.

## Local run procedure

Use a dedicated random local key and explicitly enable both guards, then bind Uvicorn to loopback:

```bash
INTERNAL_AGENT_API_ENABLED=true \
INTERNAL_AGENT_API_KEY='<dedicated-random-local-key-of-at-least-32-characters>' \
INTERNAL_AGENT_LOCAL_SERVICE_ENABLED=true \
analytics-agent-env/bin/uvicorn backend.local_agent_app:app \
  --host 127.0.0.1 --port 8771
```

Submit with `POST /internal/agent/tasks`, the key in `X-Internal-Agent-Key`, and an 8–200 character `Idempotency-Key`. The local profile runs the task synchronously through the durable runtime and returns a completed response when healthy. `GET /internal/agent/tasks/{task_id}` returns the persisted status and validated result. The result remains available only while that disposable service/database instance exists.

## Verification

Offline tests verify the default-off flags, dual-guard startup, no database creation while disabled, loopback enforcement and rejection of spoofed forwarding headers. Isolated database HTTP tests verify:

- authentication failure before planning;
- cross-scope task IDs return the same not-found response as unknown IDs;
- complete submit → durable execution → status/result flow;
- concurrent duplicate submissions are single-flight and create three Receipts once;
- a same-key/different-request conflict returns HTTP 409;
- Planner exceptions become a safe HTTP error without persistence or private detail leakage.

No paid provider is reachable: the local profile always uses the deterministic Fake Planner. No existing application database receives migrations.

Final verification passed 395 offline tests and 96 isolated database tests. A real Uvicorn smoke bound to `127.0.0.1` returned HTTP 202 with a completed task, then HTTP 200 with the same persisted result. The synthetic Q1/Q2 totals were 400.00 and 600.00 with 50.00% growth. Graceful shutdown left zero `eac_local_agent_*` databases.

## Remaining limits

This is a local integration harness, not a production Agent service. Execution is synchronous and serialized; there is no durable queue, multi-process supervisor, cancellation, backpressure, real workload identity/RBAC, rate limiting or production deployment profile. A hard process or host crash can leave the disposable database behind because graceful shutdown cannot run. Production work must also separate API and Worker lifecycles, add operator reconciliation and replace the provisional shared key.
