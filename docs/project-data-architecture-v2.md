# Product Vision v2 — 数据生命周期与项目协作架构初稿

2026-10-28 · 仅设计，未创建表、API、迁移或功能开关。参见 [愿景](product-vision-v2.md) 和 [阶段依赖](product-roadmap-v2.md)。

## 三种状态明确分离

1. **Project State（新增）**：项目目标、所有者/成员、资产引用、指标定义、已确认口径、问题/讨论、分析分支、报告与行动的持久产品状态。可跨多个执行任务继续。
2. **Analysis State（新增）**：一次分析的请求版本、必需交付物、已确认澄清、固定资产修订、假设与结果版本。新问题不重写旧结论。
3. **Execution State（复用）**：现有 Plan、Execution、Checkpoint、Receipt、Lease/CAS、幂等、Recovery/Reconciliation。说明某任务执行到哪里及结果是否确定，不授予文件权限、不定义项目记忆，也不是无限保留原始数据的依据。

拟议关系：Project → Analysis/Branch → Execution 引用；Asset → immutable AssetRevision → ParsedDatasetRevision；Analysis 固定数据版本+口径+假设；ReportRevision 固定分析结果及 provenance；Action/Goal/Observation 引用报告或分析。成员和 AssetGrant 独立绑定，运行时仍必须通过 Tool Executor 授权。

项目元数据拟用 PostgreSQL；原始文件/大结果拟用私有对象存储接口（本地可用受控目录适配器），数据库仅保存受控引用、哈希、大小、状态和策略版本。存储供应商未选。现有 RAG document/chunk 表仅在未来接入时映射 AssetRevision，不拿文本 chunk 代替表格计算数据集，也不重复建设现有向量库。

## 身份、项目与资产授权

默认私有、最小权限。产品身份由服务端认证建立，客户端 project_id 只定位对象，不能证明授权；现有固定内部 scope 不能升级宣称为真实多租户隔离。

拟议 owner/editor/viewer 是项目操作权限，不自动授予全部原始文件。每个资产区分查看元数据、读取内容用于计算、下载原始文件、分享/删除；owner 也不能转授自身无权分享的外部来源。成员邀请有指定受邀身份、过期、一次性接受和撤销；不发公开永久链接。

授权检查覆盖项目列表、资产预览/下载、任务提交、Worker 执行前、报告读取、RAG检索、导出与恢复。任务绑定服务端 principal/project/scope 和资产revision；排队后撤销访问则禁止继续读取/发布结果。执行中权限变化不能承诺撤销已发生的外部模型传输，但须阻止后续步骤与结果泄露并审计。

项目共享不等于原始文件共享，也不等于报告天然可共享：派生结果可能泄露来源。默认报告继承所依赖资产的有效权限限制；仅经显式审核生成独立脱敏结果才可扩大共享。取消成员后缓存、可下载链接和新读取必须失效，历史审计保留必要最小元数据。

## 数据生命周期与存储预算

以下数值均需 PV2-01/02 预注册，当前没有生效默认：单文件大小、sheet/行/列/单元格/解压大小限制、每用户/项目总配额、原始文件期限、回收窗口、备份轮转期限、运行日志期限。

| 对象 | 保存目的 | 删除/到期/恢复语义 |
|---|---|---|
| 原始文件 AssetRevision | 来源核验与重算 | 期限独立于项目；到期立即阻断新读取，异步清除原件/副本；无原件则不承诺可重算 |
| 解析表、chunks、embeddings、缓存 | 计算/检索派生物 | 与来源依赖追踪；删除/到期默认级联失效并清理，不能通过向量命中复活数据 |
| 分析、报告、目标/行动 | 长期项目延续 | 单独保留规则；来源缺失显示不可复算/已失效；敏感衍生内容也需删除或最小化，不能以“报告”绕过原件删除 |
| 执行/Checkpoint/Receipt | 恢复与审计 | 用受保护引用/必要结果；单独期限；清理遵守活跃租约与未知结果协调，审计不保留敏感正文 |
| 备份与删除审计 | 恢复、安全核验 | 备份有固定到期；恢复必须重新应用删除 tombstone/当前权限；清除未完成不得宣称已物理删除 |

拟议文件状态：pending → quarantined → validated/invalid → ready → expired/deleting → deleted。任何失败均保留安全状态；清理任务可幂等恢复。上传前原子预留配额，成功按实际占用结算，失败释放；派生物和待清理副本也计入可解释配额，禁止并发超额。

回收站若启用，窗口内数据仍算保存和配额，界面明确可恢复期限；立即永久删除可跳过回收。恢复需当前身份、授权、配额与保留策略校验，不复活旧共享权限。超窗/已物理删除不可恢复；备份存在不等于用户可任意取回。项目归档不自动延长文件期限；长期项目可保留最小目标与审计引用，同时重新上传获授权数据继续。

删除与任务竞争：先将资产标为不可读并递增策略版本，拒绝新读取/领取，协调在途任务；旧 Worker 不能发布撤销后结果。引用计数不阻止隐私删除，活跃任务不是无限保留豁免。源删除造成报告受影响时清楚展示，不以空值补零。

## 可信数据与分析服务边界

上传不等于验证成功。先限制文件类型/内容、扩展名/签名、路径、大小与解压预算；默认拒绝宏/外链执行，不执行任意公式或上传代码。XLSX公式及缓存值可信度、时区、日期、货币、缺失值和匹配粒度须显式策略；无法确认则集中询问或停止。CSV/XLSX 由确定性工具计算，模型只提受限计划/解释，不生成被直接执行的 Python/SQL。

解析结果带 sheet/行/列、源哈希、解析器版本、数据revision和validation问题。计算结果带公式/过滤条件/口径/单位/精度和输入版本；图表消费已验证结果，报告区分事实、解释、限制、假设及建议。模拟使用独立 scenario identity，不能覆盖实际观测值。

集中澄清记录放在 Analysis State：required_fields、缺失原因、选项、用户答案、数据/口径版本和待完成deliverables；不存模型隐式推测作为用户确认。Project State 只接纳经验证且授权保存的摘要/引用，检索或文件内指令始终是不可信数据。

## 新 API 能力草案（不是现有 Contract）

未来需要身份/会话，私有项目 CRUD，上传/状态/验证预览，项目资产授权，analysis submit/clarification/read，授权 tasks list，报告版本，保留/删除/恢复和协作邀请接口。具体 URL、schema、错误码与版本在对应工作包冻结，本轮不虚构现有路由。

旧 POST /internal/agent/tasks 与 GET by ID 仍只服务季度销售；/chat 与 /rag/chat 不变。新产品 facade 复用内部 Planner/Runtime，不能把身份/工具名/模型配置控制权交给请求。必要的新任务类型必须明确扩展和评估，不能通过兼容字段绕过旧 Validator。

提交按用户+项目+不可变payload使用幂等键；同key不同请求冲突。Project/Branch 乐观版本控制与 Execution CAS 分离。重试读状态不能创建新执行；网络失联显示未知；未知副作用仍需授权 reconciliation，不依赖唯一键声称 exactly-once。

## 项目接续、分支和协作

接续加载已授权的项目目标、确认口径、有效资产版本和结果引用，不无限拼接聊天上下文。新版本默认不静默替换历史分析数据；需要重算时创建新 Analysis/ReportRevision。分支起点固定父版本，复制逻辑引用但不自动复制或扩大原始数据权限。

并发编辑使用 project/branch version 冲突提示；早期不自动合并相互矛盾口径或结论。任何合并保留来源、作者和版本，必要时显式选择并重新计算。成员看到的上下文可能因资产权限不同而不完整，应显示安全的可见性限制，不透露受限文件名或存在性。

## 必须验证的风险与未决项

跨项目枚举/缓存泄漏、派生结果越权、删除与在途任务竞争、备份恢复复活删除数据、配额并发、压缩炸弹、公式/报告注入、口径漂移、并发分支冲突、源过期后不可重算、重复模型计费。采用 synthetic 文件、Fake/Mock、隔离数据库验证，后续真实模型仅独立授权。

本草案不承诺生产SLA或合规认证；真实身份供应商、存储/密钥管理、地域、保留期、恢复目标及协作角色最终矩阵均待专项评审。现有 frozen Prompt/评估证据继续原样保留。
